# Search & Locations

Three routers serve the search box and the map: `/api/autosuggest`
(`src/routes/autosuggest.ts`), `/api/locations` (`src/routes/locations.ts`) and
`/api/buildings` (`src/routes/buildings.ts`). They do not share an auth rule: the combined
autosuggest and the two `/locations` routes use passthrough auth (a guest is allowed, an invalid
token is a 401), while the other autosuggest routes and every buildings route resolve no JWT
middleware at all, so a token is never read and never rejected. Terms are in the
[Glossary](/glossary).

This page is the operation index. The branches, ranking and failure behaviour are on the deep
pages; the full parameter contract is in Swagger (`/swagger`).

## Operations

"Cached / header" names the cache namespace and the response header the handler writes; "none"
means neither. Every route sets `enable.xff`. Validation errors are `400`; an upstream failure
is relayed as described in [HTTP semantics](/api-reference).

| `GET /api/autosuggest`                        | passthrough | none                                                                                                      | none; up to four outbound calls (Mapbox, Repliers listings twice, Repliers locations) | 400 (validation: neither `searchSession` nor `mapboxSearchSession`, `q` shorter than 3, `resultsPerPage` above the cap); relayed upstream status when the Mapbox, listings or locations call fails | [Autosuggest](/api-reference/search-and-locations/autosuggest)                                        |

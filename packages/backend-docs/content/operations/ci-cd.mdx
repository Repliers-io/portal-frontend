# CI/CD

The repository does not ship a pipeline definition to the public; any CI system works. A
pipeline for this repository runs the migrations, the tests and the build before it deploys,
and checks the result of the release step after it.

## The test step

Run on **every pull request** and before every deploy: `npm run db:migrate` against a fresh
Postgres, then the test suite, then `npm run build`. The environment the tests need is on
[Testing](/operations/testing).

## The deploy step

Deploy the commit that passed the test step. Migrations run in the release step
([Deployment](/operations/deployment#the-release-step)), after the deploy is accepted, so check
the release result, not only the deploy trigger.

## The tag step

Optional: tag the deployed commit so the shipped version can be found later.

## Branch model

Map branches to deployment targets in the pipeline, not in code. Which settings preset an
environment runs is decided by its `APP_SETTINGS_PRESET`, not by the branch (see
[Instances](/operations/instances)).

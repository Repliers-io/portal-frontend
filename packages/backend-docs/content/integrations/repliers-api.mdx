# Repliers API

The upstream MLS data provider — the reason this backend exists. Everything about
the client-side mechanics is in [Architecture → Repliers Proxy](/architecture/repliers-proxy)
(axios instance, throttling, error mapping), [Client IP forwarding](/architecture/client-ip-forwarding)
(XFF, warmup key) and [MLS-number prefix](/architecture/mls-number-prefix); this page
covers the account/operational side and lists every endpoint the backend calls.

## Keys and boards

- `REPLIERS_API_KEY` — the main key. A **free sample-data key** (board 110) is
  available at [login.repliers.com](https://login.repliers.com/) and is what the
  default preset targets — the whole backend runs against it.
- Paid keys are scoped to one or more real estate **boards**; the instance preset
  must mirror that scope (`settings.defaults.boardId`, `scrubbing.board_ids`,
  `APP_DEFAULTS_BOARDIDS`).
- `REPLIERS_API_KEY_EXTRA` — optional second key for the historical listings behind
  estimate property details (`EstimateService` applies it with `switchKey`).
- `REPLIERS_CACHE_WARMUP_API_KEY` — optional key for SSG traffic (builds, ISR, warm-up
  scripts), so it never spends the live key's quota — see
  [Client IP forwarding](/architecture/client-ip-forwarding#contexts-register). Provision
  it with entitlements no broader than the main key.

## Rate limits

Live requests share one process-wide throttle: `REPLIERS_API_LIMIT` requests per
`REPLIERS_API_INTERVAL_MS` (default 1/second). With a warmup key configured, SSG
traffic runs on its own throttle (`REPLIERS_CACHE_WARMUP_API_LIMIT` /
`REPLIERS_CACHE_WARMUP_API_INTERVAL_MS`). A Repliers 429 reaches the client as a 429
with the upstream body in `info`; upstream headers, `Retry-After` included, are not
forwarded.

## Repliers endpoints

Every Repliers call goes through a method of a class in `src/services/repliers/` (all extend `RepliersBase`, `src/services/repliers/base.ts`); no other file builds a Repliers URL.

**Key used.** A method uses `REPLIERS_API_KEY` (main) unless a row says otherwise. A request that carries the SSG token uses `REPLIERS_CACHE_WARMUP_API_KEY` instead (warmup) when that is set. `RepliersBase.switchKey` replaces either with another key; its only caller is `EstimateService`, which moves its second `RepliersListings` instance (`historicalListings`) onto `REPLIERS_API_KEY_EXTRA` (extra) when that is set. Outside an HTTP request the main key is used. See [Client IP forwarding](/architecture/client-ip-forwarding#contexts-register).

**Caching.** The client classes cache nothing. The column names the caching of the domain method that calls the client: "none" means that method is not decorated with `@cached`; a `@cached` method stores its result under the namespace shown (see [Caching](/architecture/caching)). Methods decorated with `@scrubbed` scrub on every call.

## Query semantics worth knowing

Verified behaviors that shape how the backend builds requests:

- **`queries[]` is a union** (POST search) — and a parameter present both top-level
  and inside `queries[]` is rejected with `400 Parameter conflict`. Exclusions
  (`not:mlsNumber`) must therefore be placed per the rules in
  [Restricted listings: placing `not:`](/architecture/restricted-listings#placing-not-on-a-search).
- **`search` is a per-keyword, case-insensitive starts-with match**; with
  `searchOperator=OR` + `address.streetNumber` in `searchFields`, a digit keyword
  that matches no street number zeroes the whole union — the reason MLS-prefix
  search-widening is confined to the autosuggest MLS leg.
- **Repeated `mlsNumber` params form a union**; an exact-number lookup changes other
  defaults upstream — verify against the live API when in doubt.
- **`standardStatus` cannot be combined with `status` / `lastStatus`** — Repliers
  answers `400`. On an instance with `APP_ALLOWED_LISTINGS_STANDARD_STATUSES`,
  `constrainStandardStatus` (`services/listings/listingHelpers.ts`) narrows
  `standardStatus` onto every listings and favorites query, including each
  `queries[]` branch: no filter means every allowed status, never every status. So
  every caller on such an instance must filter in the RESO vocabulary — stats use
  `Closed` / `Active`, autosuggest uses `REPLIERS_AUTOSUGGEST_LISTING_STANDARD_STATUS`.
  RESO values are case-sensitive (`Active Under Contract`).

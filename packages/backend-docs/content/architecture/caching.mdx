# Caching

The backend caches Repliers and statistics results in [Keyv](https://keyv.org/) stores, one
store per **namespace**, written by the `@cached` decorator. Two more Keyv stores hold
one-time passwords and revoked tokens; they are state, not caches. Terms are in the
[Glossary](/glossary).

## Keyv stores

`CacheFactory` (`src/lib/decorators/cached.ts`) creates one `Keyv` per namespace the first
time a decorator names it and reuses that instance for the process lifetime. The decorator
resolves its store when the class is defined (module load), not per request, so every
request-scoped service instance reads the same store.

| Backend                        | Selected by                                                                                          | Scope                                                         | After a restart              |
| ------------------------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ---------------------------- |
| In-memory (Keyv default `Map`) | `REDIS_KEYV_ENABLE` unset or not `"true"`                                                            | One process: each process has its own copy of every namespace | Empty                        |
| Redis                          | `REDIS_KEYV_ENABLE=true`; URL from `REDIS_URL`, else `REDISCLOUD_URL`, else `redis://localhost:6379` | Every process that points at the same Redis and namespace     | Entries live until their TTL |

With Redis, each store constructs its own `new KeyvRedis(url)` and passes it to
`new Keyv({ store, namespace })`. Reading `keyv` 5.6.0 and `@keyv/redis` 5.1.6: Keyv keeps
`useKeyPrefix` on, so it prefixes every key with `<namespace>:`, and it also sets the
namespace on the Redis adapter, which prefixes `<namespace>::` (the adapter turns
`useKeyPrefix` off only in its own `createKeyv` helper, which this code does not use). The
literal Redis key is therefore probably `<namespace>::<namespace>:<JSON args>`; that was read,
not observed, because no Redis was run. Entries carry a TTL set at write time (`cache.set(key, value, ttl_ms)`); in
memory an expired entry is treated as absent when read. Nothing sweeps the in-memory store
and nothing bounds its size.

### Stores that are not result caches

`keyv.otp` (namespace `otp`) and `keyv.blocklist` (namespace `blocklist`) are built by
providers (`src/providers/keyv.otp.ts`, `src/providers/keyv.blocklist.ts`) with the same
`REDIS_KEYV_ENABLE` switch, but they hold one-time codes and revoked-token ids. Their keys,
values and lifetimes are in [Keyv stores own their data](/architecture/data-ownership#keyv-stores-own-their-data)
and their use in [Authentication](/architecture/authentication). Without Redis they are
per-process too: a code issued by one process is unknown to another.

## The `@cached` decorator

```ts
// src/services/listings.ts
@cached("listings:count", config.cache.listingscount.ttl_ms)
async count(params) { ... }
```

Mechanics (`src/lib/decorators/cached.ts`):

- **Key.** `JSON.stringify(args)`: every argument, in order, so object key order and array
  order are part of the key and `undefined` object properties are dropped (an `undefined` array element becomes `null`). The
  namespace is not part of the argument string; the Keyv layers add their prefixes
  ([Keyv stores](#keyv-stores)).
- **Stored value.** `{ data, created }`, `created` being the write time in Unix seconds.
- **Hit.** Returns `{ result: data, expires }`, `expires` being the TTL in seconds minus the
  whole seconds elapsed since `created`.
- **Miss.** Calls the original method, starts `cache.set(key, ..., ttl_ms)` without awaiting
  it, and returns `{ result, expires }` with `expires` the full TTL in seconds. Concurrent
  misses on one key each call the method; there is no single-flight.
- **Errors.** A method that throws caches nothing.
- **Response.** Routes pass the value to `sendCached(ctx, data)`, which, when the value is an
  object with an `expires` key, writes `result` as the body and sets
  `Cache-Control: private, max-age=<expires>`; any other value is sent as it is with no header
  ([HTTP semantics](/api-reference)). Two identical requests therefore see a decreasing
  `max-age` until the entry expires.

### Typing quirk

A `@cached` method's declared return type is `Promise<T | Cached<T>>` even though it
always returns `Cached<T>` at runtime — TypeScript cannot see through decorated
return types. `sendCached` handles both shapes, and internal callers that need the data
read `.result` (`ListingsService.countArray`, `StatsService.neighborhoodsrankingAuthorised`).

### When _not_ to cache — the `app_state` trap

The key is `JSON.stringify(args)`, so any argument that differs per caller becomes part of
the key. `app_state` is the per-request object that carries the JWT user for the scrubber.
The listing methods that take it (`search`, `single`, `history`, `similar`) carry
`@scrubbed` and no `@cached`; none of the ten `@cached` methods above receives `app_state`
in its arguments:

- `count` uses a schema that omits `app_state`, and the count routes do not add it.
- Featured listings take `app_state` in the public method, strip it with
  `const { slug, app_state, ...query } = params`, cache the inner `cachedFeaturedListings(slug,
sortBy?)`, and run `@scrubbed("listings")` on the unwrapped result. The cache holds the
  list before scrubbing; the scrubbing decision is made per request ([Scrubbing](/architecture/scrubbing)).
- `neighborhoodsranking` takes the user only to choose between the stub and
  `neighborhoodsrankingAuthorised(params)`; the user is not an argument of the cached method.

Before adding `@cached`, read what the method's arguments contain.

## Gotchas

1. **Only the featured namespace is ever cleared by code.** Every other namespace lives
   until its TTL, per process unless Redis is on ([Keyv stores](#keyv-stores)). Source:
   `src/services/favorites.ts` (`invalidateFeaturedListingsCache`), the only use of
   `getCacheStore`.
2. **`max-age` can differ from the configured TTL.** On a hit it is the remaining lifetime;
   on a miss it is the full TTL. A client that stores the response honours the remaining time.
   Source: `src/lib/decorators/cached.ts` (`sendCached`, default export).
3. **Routes that bypass `sendCached` expose different shapes.** `GET /api/buildings/{addressKey}`
   returns the `{ result, expires }` object; `POST /api/listings/count` and the featured route
   return plain values with no `Cache-Control`. Source: `src/routes/buildings.ts`,
   `src/routes/listings.ts`.
4. **Argument order and defaults decide the key.** Two requests with the same meaning but
   differently ordered arrays, or a defaulted versus an explicit value, are separate entries.
   Source: `src/lib/decorators/cached.ts` (default export, `JSON.stringify(args)`).
5. **`stats` and `nr` are an inner and an outer cache.** `nr` calls `fetchStats` through the
   `stats` namespace, so a `nr` miss may still be served from `stats` (both 24 h by default).
   Source: `src/services/stats.ts` (`neighborhoodsrankingAuthorised`, `fetchStats`).

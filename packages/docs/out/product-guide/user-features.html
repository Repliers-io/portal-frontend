User Features

Portal provides authenticated users with personalized features to save properties, searches, and receive alerts.

Technical anatomy (providers, routes, config) is in How it works.

Feature Overview

FeatureURLDescription
Favorites/favoritesSaved properties
Image Favorites/image-favoritesSaved listing photos
Saved Searches/saved-searchesSaved filter combinations
Recently Viewed/recently-viewedBrowsing history
Profile/profileAccount settings
Alerts(email)Notifications for new matches (part of saved searches)

Authentication

These features require a signed-in user. The portal uses passwordless authentication — there are no passwords to set or store. Sign-in options:

MethodDescription
Email or phone + OTPA one-time code is sent to the user’s email or phone to verify sign-up / sign-in — no password
Google OAuthSign in with Google

The email/phone OTP flow is gated by the messaging feature flag. A tenant without messaging shows only Google sign-in; with it, the OTP form and Google appear together (separated by an “or” divider).

OTP flow

The auth dialog has two flows — login and sign-up — each a two-step input → verify:

   Enter email / phone          Enter the code
   ┌──────────────┐   code sent  ┌──────────────┐   verified   ┌──────────────┐
   │    input     │ ───────────▶ │    verify    │ ───────────▶ │  signed in   │
   └──────────────┘              └──────────────┘              └──────────────┘
  1. The user enters an email or phone number (APIAuth.login) and the portal sends a one-time code.
  2. They enter the code (loginWithOtp) and are signed in — the original member action (e.g. saving the favorite that opened the dialog) then completes.
  • Auto-switch, no upfront choice. Submitting an unknown email/phone during login flips to sign-up (which also collects first/last name); an existing user during sign-up flips back to the login code prompt.
  • Resend is rate-limited by a 60-second cooldown.
  • The last-used email/phone is remembered (localStorage) and pre-fills the next visit.
  • Google (GoogleSignInButton) is offered as a one-tap alternative to the code flow.

For the token/JWT flow, the provider union (google | facebook | otp), roles, and refresh, see Authentication & Authorization.

Favorites

Save properties for later viewing and comparison.

How It Works

  1. User clicks heart icon on property card or detail page
  2. If not logged in, auth modal appears
  3. Property is saved to user’s favorites
  4. User can view all favorites at /favorites

Favorite Actions

ActionDescription
AddClick heart to save
RemoveClick heart again to unsave
View AllGo to /favorites page
SortBy date added, price, etc.
CompareSide-by-side comparison

Data Stored

FieldDescription
listingIdMLS listing ID
userIdUser ID
createdAtWhen saved
notesUser notes (optional)

Saved Searches

Save search filter combinations to reuse and receive alerts.

How It Works

  1. User applies filters on search page
  2. Clicks “Save Search” button
  3. Names the search (e.g., “Seattle Condos Under 500K”)
  4. Optionally enables email alerts
  5. Search is saved to /saved-searches

Saved Search Data

FieldDescription
nameUser-defined name
filtersAll search parameters
alertEnabledEmail notifications on/off
alertFrequencyDaily, weekly, instant
createdAtWhen created
lastAlertAtLast notification sent

Alert Options

FrequencyDescription
InstantEmail when new listing matches
DailyDaily digest of new matches
WeeklyWeekly summary
OffNo notifications

Image Favorites

Save individual listing photos (not whole listings) — useful for collecting interior ideas, finishes, and layouts across different properties.

  • Click the favorite control on a photo in the gallery.
  • All saved photos are shown at /image-favorites.
  • Gated by the imageFavorites feature flag (separate from favorites).

Recently Viewed

Automatic browsing history for authenticated users.

How It Works

  • Each property detail page view is logged
  • History shows last 50 viewed properties
  • Displayed at /recently-viewed
  • Cleared on user request

Data Stored

FieldDescription
listingIdProperty viewed
viewedAtTimestamp
durationTime on page (optional)

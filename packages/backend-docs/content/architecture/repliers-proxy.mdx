# Repliers Proxy

All upstream traffic goes through the client family in `src/services/repliers/`:

```
services/repliers/
├── base.ts        # RepliersBase — axios instance, throttling, XFF, error mapping
├── listings.ts    # search / single / similar / history …
├── locations.ts   # locations & autocomplete
├── estimate.ts    # AVM estimates
├── favorites.ts   # favorites
├── searches.ts    # saved searches
├── clients.ts     # Repliers clients (users)
├── agents.ts      # agents
├── messages.ts    # Messages API (OTP, inquiries)
├── buildings.ts   # buildings
└── normalize.ts   # response normalization helpers
```

`services/repliers.ts` (`RepliersService`) bundles the nine clients (`listings`, `messages`,
`clients`, `favorites`, `searches`, `estimate`, `agents`, `locations`, `buildings`) for
services that need several. The register of every method, the Repliers path it calls, the
key it uses and its callers is on [Repliers API](/integrations/repliers-api#repliers-endpoints).

Domain services (`services/listings.ts`, `services/estimate.ts`, …) depend on these
clients; nothing outside `services/repliers/` builds a Repliers URL.

## `RepliersBase`

- One axios instance per client, `baseURL = config.repliers.base_url`, the API key in
  the `REPLIERS-API-KEY` header, `Content-Type: application/json`, `timeout` from
  `REPLIERS_TIMEOUT` (default 30000 ms). Array query values are serialized as repeated
  keys (`paramsSerializer: { indexes: null }`), not as `key[]=`.
- **No retry.** A failed call is not repeated; the throttle and the timeout are the only
  controls around it. A client resolved through the request container is a new instance
  per request; the two throttles are process-wide singletons.
- **Throttling** — every request goes through a `p-throttle` wrapper with an
  `onDelay` hook that is an empty function (`src/providers/throttler/ondelay.ts`), so a
  throttled call is not logged. The wrapper is around `axiosInstance.request`, so time in
  the queue is not counted by the axios timeout
  ([retry layers](/architecture/failure-and-degradation#retry-layers)). There are two, both container singletons, so each limit
  is process-wide: `throttler:repliers` (`providers/throttler/repliers.ts`, at most
  `REPLIERS_API_LIMIT` requests per `REPLIERS_API_INTERVAL_MS`) carries live traffic;
  `throttler:repliers:warmup` carries SSG traffic once a warmup key is configured —
  see [Client IP forwarding](/architecture/client-ip-forwarding#contexts-register).
- **Key switching** — `switchKey(key)` rebuilds the axios instance and keeps the
  active throttler. Its caller is `EstimateService` (`src/services/estimate.ts`), which
  moves its historical-listings client onto `REPLIERS_API_KEY_EXTRA` when that key is set.
- Upstream failures are mapped to `ApiError("Repliers API error: <status>")` with the
  upstream status, and the upstream response body travels in the error's `info`; the
  [global error handler](/architecture/request-lifecycle#error-handling) shapes them
  like any other error. Upstream headers (`Retry-After` included) are not forwarded.

## Executed checks

- Existing frontend suites: **28 suites, 296 tests passed** across search/API,
  listing, conversion, forms, CMS widgets, locations and building assembly.
- Shared checker fixtures: **3 tests passed**, including intentional broken
  links/anchors/images and base-path handling.
- Tutorial snippets: **3 temporary fixture tests passed** for filter state,
  widget parsing/validation and overlay merging. Widget JSX/registry syntax was
  transpiled; the proposed component was not installed or fully type-checked.
- Frontend standalone and static builds generated all 75 documentation pages and
  Pagefind entries. Integrity checks retained all 468 original anchors; frontend
  TypeScript passed. The shared checker passed against the backend's existing
  57-page static output, and backend TypeScript passed; no fresh backend build
  was performed for this frontend content change.
- Live environment: user-confirmed `defaults` frontend at localhost:3000 and
  sample-data proxy at localhost:8080. The initial backend mismatch was corrected
  by the user before recording the successful search trace.
- Browser search: 500 results before filtering, 299 after `minBedrooms=2` and
  `minPrice=600000`; reopening the generated URL retained those filters and the
  observed result. Counts are a snapshot, not permanent expected values.
- The selected listing's direct URL rendered matching MLS identity, price,
  bedrooms and area. The search-dialog click is not counted as verified; see
  [F04](/technical-guide/workflows/listing-and-auth#executed-detail-example).
- Edge browser checks covered readable diagram text and scrolling at 1280px and
  390px widths, the API register, widget tutorial, Pagefind results and a result
  anchor, plus static navigation to backend docs and the shared hub.
- All **17 diagrams** rendered in the standalone browser pass without Mermaid
  errors. Standalone Pagefind navigation and the mobile menu also reached their
  intended articles; the twelve workflows each have a sequence diagram.

The local static-file preview returned 404 for Next's dotted RSC prefetch paths
while exporting the corresponding segments as directories. The observed search
result still reached its article/anchor through navigation fallback. This is a
recorded delivery limitation, not a clean-console or deployed-rewrite claim;
the portal's hosting behavior needs its own integration check.

## Explicit limits

No account mutations, real contact messages, CRM deliveries, OTP/OAuth exchanges,
remote CMS publishing, location regeneration, tenant export, production cache
invalidation or deployment were executed. Proposed tutorial components/config
changes are examples, not application changes. Existing screenshots and every
tenant fork have not been visually re-certified. External protocol and raw-response
limitations are documented as current behavior, not silently repaired here.

## Keeping this edition current

When a source owner changes, update its register and corresponding workflow,
record the new revision/evidence, run the smallest relevant tests and the docs
checker, and review affected screenshots/diagrams. Preserve old routes and anchors;
do not replace the baseline simply to make a removed heading pass.

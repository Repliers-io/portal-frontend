# Glossary

Terms below describe what a word means **in this backend**, and which similar-looking thing it is not. They are not guarantees that every endpoint treats an identifier the same way; follow the linked page for a concrete route. Where an identifier has an owner and a lookup rule, the full register is on [Data ownership](/architecture/data-ownership#identity-and-ownership).

## Identifiers of people

| Term                                     | Meaning here                                                                                                                                                                                                                                                                                                                                                                    | Do not confuse with                                                                                           |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| <span id="clientid" />`clientId`         | Numeric id of a **Repliers client** record, the primary record of a portal user. The backend never stores it as a user row of its own; it carries it in the JWT (as `sub`), in Repliers request bodies and in the local `people_sync.client_id` column.                                                                                                                         | `agentId`; the FUB person id (`externalId` holds that); the JWT `jti`; a database primary key of this backend |
| <span id="jwt-sub" />JWT `sub`           | Claim holding **one id as a string, whose meaning depends on how the token was issued**. Client sessions (OTP, email token, OAuth for an existing or newly created client) carry the `clientId`. An OAuth sign-in by an agent carries the `agentId`. The FUB embed token has **no** `sub`. Routes read it as `ctx.state["user"].sub` and pass it on as `clientId` or `agentId`. | Always being a `clientId`; a user id of a local table (there is none)                                         |
| <span id="jti" />`jti`                   | Random UUID given to every issued token. Logout and refresh store it in the blocklist (a Keyv namespace, not SQL) until the token would have expired; a token without a `jti` is treated as revoked.                                                                                                                                                                            | The OTP code; the `sub`                                                                                       |
| <span id="agentid" />`agentId`           | Numeric id of a **Repliers agent**. Every client record names its assigned agent by `agentId`; the configured default agent (`REPLIERS_AGENT_ID`) is the fallback for guests, new signups and unmatched CRM people.                                                                                                                                                             | `clientId`; the FUB user id (`externalId` on the agent holds that)                                            |
| <span id="fub-person-id" />FUB person id | The `id` of a person in Follow Up Boss. Stored upstream as the Repliers client's `externalId` and locally in `people_sync.people_id`.                                                                                                                                                                                                                                           | `clientId`; the FUB user id                                                                                   |
| <span id="fub-user-id" />FUB user id     | The `id` of a user (an agent or team member) in Follow Up Boss, the value of a person's `assignedUserId`. Stored as the Repliers **agent's** `externalId`, in `people_sync.user_id` and, for agents who sign in through OAuth, in the JWT claim `external.fub_id`.                                                                                                              | The FUB person id; the `agentId`                                                                              |
| <span id="externalid" />`externalId`     | Free link field on Repliers **clients and agents** that points at the CRM record: on a client it is the FUB person id, on an agent the FUB user id. The backend sets it when it creates a client from a CRM person and reads it to find the person again. It travels as a string in filters and as a number in the create DTO.                                                  | The `clientId` / `agentId`; an id the backend generates                                                       |
| <span id="acl" />ACL                     | The local `acl` table: one row per email address with a numeric role. It is the only source of the `Admin` and `Root` roles, and while persistence is enabled it overrides the role claim whenever a token is issued (with `APP_DISABLE_PERSISTENCE=true` the table is not read).                                                                                               | A permission list per route; Repliers-side access rules                                                       |

## Identifiers of listings and records

| Term                                 | Meaning here                                                                                                                                                                                                                                                                                                | Do not confuse with                                                                           |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| <span id="mlsnumber" />`mlsNumber`   | A listing's number **inside one board**. When the `mlsNumberPrefix` setting is non-empty the backend strips the prefix from every Repliers response and adds it back to every request, so API consumers always see the clean number; both directions are idempotent and the `raw` payload is left verbatim. | A globally unique listing id (pair it with `boardId`); the prefixed value the upstream stores |
| <span id="boardid" />`boardId`       | Numeric id of an MLS board in Repliers. A request may carry a list of them (the default comes from the preset or environment); each listing reports its own `boardId`; the scrubbing and event-collection settings key on it.                                                                               | The preset name; a deployment; an upstream account                                            |
| <span id="addresskey" />`addressKey` | Opaque address-derived key that Repliers assigns. The backend does not compute it: it accepts it as the path segment of `GET /api/buildings/{addressKey}` and as a listings filter and forwards it unchanged.                                                                                               | A guaranteed property or parcel identifier                                                    |
| <span id="estimateid" />`estimateId` | Numeric id of a **Repliers estimate**. An estimate made by a guest has no `clientId`, so nobody passes the ownership check for it; for a signed-in user it belongs to that `clientId`, and an agent owns the estimates of their own clients.                                                                | The estimated price; a listing id                                                             |
| <span id="searchid" />`searchId`     | Numeric id of a **Repliers saved search**. Deleting one is allowed after the backend finds it in the caller's own searches.                                                                                                                                                                                 | A search request of `GET /api/listings`, which is not stored                                  |
| <span id="favoriteid" />`favoriteId` | Numeric id of a **Repliers favorite**, i.e. the link record between a client and a listing. Deleting one is allowed after the backend finds it in the caller's own favorites.                                                                                                                               | The `mlsNumber` of the favorited listing                                                      |

## Configuration

| Term                           | Meaning here                                                                                                                                                                                                                                                                                                                                                                                     | Do not confuse with                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| <span id="preset" />preset     | A settings file chosen at startup by `APP_SETTINGS_PRESET` (`src/settings/defaults.ts` or one file under `src/settings/instances/`). It is merged over the configuration built from the environment, so a value set in the preset wins over its environment variable; arrays replace instead of merging. An unknown name logs a warning and the process continues on environment variables only. | An upstream account or tenant; anything chosen per request                           |
| <span id="instance" />instance | One running deployment of this codebase: a web process, optionally the NATS worker, with one environment and one preset. "Switching boards" means starting a different instance, since configuration cannot change at runtime.                                                                                                                                                                   | A preset file (an instance uses exactly one); a process or dyno of the same instance |

## Callers

The role is a number in the JWT `role` claim (`UserRole` in `src/constants.ts`). Whether a caller is a guest is decided by the presence of a valid token on a route that tolerates its absence.

| Term                     | Meaning here                                                                                                                                                                                                                                                                                                    | Do not confuse with                                |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| <span id="guest" />guest | A request **without a token** on a route that uses the passthrough middleware. `ctx.state["user"]` is empty. Listings are scrubbed more strictly; contact messages go out under the configured guest `clientId` and default agent. A request with a **broken or expired** token is an error (401), not a guest. | An authenticated user with no favorites            |
| <span id="user" />user   | A caller whose token has role `User` (2): a Repliers client signed in by OTP, email token or OAuth. This is the default role when no ACL row says otherwise.                                                                                                                                                    | A row in a local users table (there is none)       |
| <span id="agent" />agent | A caller with role `Agent` (4). Three paths issue it: an OAuth sign-in whose email matches an active Repliers agent and no client, the signed FUB embed login, and an ACL row. Agent tokens have a shorter default lifetime (`AGENT_JWT_EXPIRE`). Agent routes accept `Agent` and `Admin`.                      | The `agentId` itself; a person using the user role |
| <span id="admin" />admin | A caller with role `Admin` (3), granted only by an ACL row. It opens the admin routes and the virtual-tour mutations, and also passes the agent routes.                                                                                                                                                         | The word "administrator" of a deployment           |
| <span id="root" />root   | Role `Root` (1), also granted only by an ACL row. The `/api/admin` routes and the `/api/vtour` writes admit `Admin` and `Root`; `/api/agent` admits `Agent` and `Admin`, not `Root` ([Agents and roles](/architecture/authentication#agents-and-roles)).                                                        | A superuser of the database                        |

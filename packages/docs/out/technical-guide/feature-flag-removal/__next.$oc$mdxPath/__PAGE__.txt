# Feature Removal

When a [feature flag](/getting-started/capabilities-and-flags) is permanently OFF for a
tenant, the code behind it is still shipped — it just never renders. For a slimmed tenant
build (e.g. a standalone frontend export) you can physically delete that code. This page
maps, per flag, **what is actually deletable** versus what must stay because it is shared.

<Callout type="info">
  Deletable surface is very uneven across flags. "Big flag" does not mean "big
  deletion": route-gated features (`estimate`, `blog`) delete cleanly, while
  data-layer features (`locations`, `map`) look huge but their
  config/API/service spine is shared app-wide.
</Callout>

## How flags gate code

Each App Router page checks the flag and 404s when it is off:

```tsx
// app/<route>/page.tsx
if (!features.locations) return <Page40XTemplate />
```

The route still exists and the whole imported subtree stays in the bundle — so **deletable =
everything exclusively reachable from that feature**. Anything imported by another feature is
shared and must stay.

<Callout type="warning">
  **Utilities are mostly kept.** Helpers in `src/utils/` genuinely stitch
  features together (URL building, formatters, filters, listing visibility).
  Treat a util as deletable only when it is provably feature-exclusive.
</Callout>

## Removal ROI at a glance

| Tier                | Flags (approx. exclusive files)                                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Best — isolated** | `estimate` ~400 · `buildings` ~125 · `blog` ~61 · `dashboard` ~35                                                                                       |
| **Solid**           | `aiQuality` ~20 · `messaging` ~18 · `saveSearch` ~17 · `aiChat` ~15 · `aiImageSearch`(+`aiSearch`) ~15 · `liveBy` ~15                                   |
| **Small & clean**   | `favorites` ~11 · `imageFavorites` ~10 · `aiAgent` ~10 · `profile` ~9 · `recentlyViewed`/`openHouse`/`aiSpaces` ~4 · `aiSearch` ~3 · `cookieConsent` ~1 |
| **Deceptive**       | `locations` (57 pages, data layer shared) · `map` (~500 files but core) · `blurRestrictedProperty` (0 files)                                            |

## Route-gated features

These own a self-contained App Router route + page-component tree — the cleanest deletions.

## Account & personalization

Route pattern `app/(ClientPages)/<route>/page.tsx` + `components/pages/<page>/**`. The trap:
the **provider/hook** is usually mounted app-wide and driven by a button on listing cards or
the map, so it survives the page — unless that button is itself flag-gated.

- **`recentlyViewed`** — ~4 files. route + `components/pages/recently-viewed/**`. No provider/API → fully deletable.
- **`profile`** — ~9 files. route + `components/pages/profile/**` (incl. Unsubscribe, FeedbackForm). No provider/API → fully deletable.
- **`favorites`** — ~11 files. route + `components/pages/favorites/**` + `FavoriteRemoveDialog.tsx` + `FavoritesMenuItem.tsx` + `services/API/APIFavorites.ts`. Keep `FavoritesProvider`+`useFavorites` (listing-card favorite button).
- **`imageFavorites`** — ~10 files. route + `components/pages/image-favorites/**` + `ImageFavoriteRemoveDialog.tsx` + `AiSearchDialog/components/ImageFavorites{Browser,Item,List}.tsx` + `ImageFavoritesMenuItem.tsx` + `services/API/APIImageFavorites.ts`. Keep `ImageFavoritesProvider`+`useImageFavorites` (photo StarButton).
- **`saveSearch`** — ~17 files. route + `components/pages/saved-searches/**` + `MapFilters/components/SaveSearchButton.tsx`+`useSaveSearchButton.tsx` (+`_movesmartly` fork) + `SaveSearchDialog/**` + `SaveSearchRemoveDialog.tsx` + `SaveSearchMenuItem.tsx`. Keep `services/API/APISavedSearch.ts` + `SaveSearchProvider/utils.ts` (used by `search/[layout]` for `?searchId=` hydration).

## AI features

Not route-gated. **Shared core stays if any relevant flag is on:** `providers/AiSearchProvider.tsx`,

- **`aiAgent`** — ~10 files. `components/pages/search/components/SupportAgent/**` (EVAS iframe + postMessage). Independent.
- **`aiChat`** — ~15 files. `search/.../MapRoot/components/ChatContent/**` (desktop NLP panel). Independent render.
- **`aiQuality`** — ~20 files. `GalleryDialog/components/{GalleryTabs,GalleryGroupsView,InspectionGroup}` + `AdvancedFiltersDialog/components/AiQualityFiltersTab/**` + quality sort modes + `getQualityTag`. Independent.
- **`aiSearch`** — ~3 files. `MapFilters/components/AiSearchButton/**`. Dialog shared with `aiImageSearch`.
- **`aiImageSearch`** — ~15 files. `shared/Dialogs/AiSearchDialog/**` (+ `shared/Photos/AiSubmitButton.tsx`). Deletes **only if `aiSearch` is also off** (composite gate).
- **`aiSpaces`** — ~4 files. `MapFilters/components/AiSpacesSelect/**`. Feature browser lives in the shared AiSearchDialog.

### `liveBy` — demographics + overlays · ~15 exclusive (+~30 overlay engine, tenant-dependent)

Delete (liveBy-exclusive): `providers/LiveByDemographicsProvider.tsx`, `pages/listing/.../LiveByDemographics/**`,
`shared/Map/OverlayMarkerPopup/LiveBy*Card.tsx`, `configs/defaults/overlays/liveBy.ts`,
`ListingBrowserDialog/hooks/useListingDemographics.ts`, i18n `liveByDemographics`.

<Callout type="warning">
  The overlay **engine** (`shared/Map/hooks/useOverlayLayers/**`,

  `OverlayToggleButton`, `app/api/{schools,social-housing,parcel,mapbox/pois}/**`) is deletable

  `shared/Map/markerElement.ts`, `MapOptionsProvider`, tenant `configs/<t>/map.ts`, `services/MoveSmartly/**`.

### `map` — interactive search (CORE) · ~500 files, but not cleanly isolatable

Delete (interaction layer): `app/search/**`, `app/listing/**`, `components/pages/search/**` (~139),
`components/pages/listing/**` (~215), `components/shared/Map/**` (~68), `services/Map/**`,
`providers/SearchProvider/**`, `MapOptionsProvider/**`, `ListingProvider.tsx`/`ListingDetailsProvider.tsx`/`ListingEnrichmentProvider.tsx`.

<Callout type="warning">
  **Blockers — keep (foundational, reused by
  favorites/dashboard/locations/estimate/widgets/carousels):**
  `components/shared/Listing/**` (ListingCard/DrawerListingCard),
  `@configs/filters` (~45 consumers), `services/API/APISearch.ts` +
  `APIListingDetails.ts`, and `MapOptionsProvider` (embedded maps in
  listing/locations). Map is the **interaction** layer;
  listings/filters/cards/APIs are the **data** layer, baked throughout. Verify
  each `SearchProvider`/`MapOptionsProvider` wrap in non-map pages before
  removing.
</Callout>

  `ThirdPartyLoginForm`).
</Callout>

## Rules of thumb

- **Route-gated** features (`estimate`, `blog`, `dashboard`, `buildings`) delete cleanest — the page tree is self-contained.
- **Provider-backed** features (`favorites`, `saveSearch`, AI) delete the page but keep the app-wide provider unless its trigger (card/map button) is also flag-gated.
- **Data-layer** features (`locations`, `map`) look huge but the config/API/service spine is shared — only the pages/interaction delete.
- **Cross-tenant / CMS infra** (WordPress client, `ContactForm`, the overlay engine) is shared — verify per-tenant before a global deletion.
- **Watch the hidden gates:** `messaging` → OTP auth · `buildings` → MLS condo listings · `estimate` ↔ `dashboard` Statistics.

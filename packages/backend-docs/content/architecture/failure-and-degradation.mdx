# Failure & degradation

What happens when a dependency or a stage fails: whether the error is caught or propagates, what
the caller or the task gets, what has already happened by then, and whether the code retries or
falls back. A successful response, a committed row, a published message and a finished worker job
are separate outcomes; this page keeps them apart. How a thrown value becomes a response body is on
[Request lifecycle: error handling](/architecture/request-lifecycle#error-handling); what stops a
whole process is on [Process lifecycle](/architecture/process-lifecycle). Terms are in the
[Glossary](/glossary).

## Variation

- **Production vs other environments.** Variant 5 adds `err`, `stack` and `file` to the body when
  `NODE_ENV` is not `production` (`src/app.ts`); `NODE_ENV` unset counts as `production`
  (`src/config.ts`, `env`).
- **`BOSS_ENABLED=false`.** FUB calls return `{}`; request paths that read a field of the result
  then fail or find nothing, and the webhook route answers 500 for created and updated events
  ([variation](/integrations/follow-up-boss#variation)).
- **`NATS_ENABLED=false`.** Publishing succeeds without storing anything; see the `DummyNats` row.
- **`REDIS_KEYV_ENABLE` unset.** No Redis dependency, and therefore no Redis failure mode; the
  stores are per process.

## Evidence

- Source: the files in each Source cell.
- Executed on 2026-10-20: `src/app.ts` imported in-process with placeholder values for the four
  required variables, no env file and no preset, served on a random local port; the Repliers base
  URL pointed at a local server that never answers (`REPLIERS_TIMEOUT=800`), the Mapbox base URL
  and `DB_PORT` at closed ports. Results: `GET /api/locations` 500 with
  `undefined - Repliers API error: undefined - /api/locations` after the timeout;
  `GET /api/autosuggest/address` with a session 500 `Internal Server Error` with the `TypeError`
  in the debug fields (`NODE_ENV=development`); `GET /api/vtour/some-slug` 500 at once on
  `ECONNREFUSED`; a request without a session 400 from Joi.
- Executed the same day: `keyv` with `@keyv/redis` as built by `src/providers/keyv.otp.ts`, against
  a closed port, without and with an `error` listener: `get` and `set` were pending after 8 s each
  and no exception reached the process.
- Not established by this checkout: how long a Keyv call waits beyond 8 s, Redis or NATS behaviour
  after a connection that was working drops, the NATS server's redelivery limits, FUB's
  redelivery of a failed webhook, and Repliers' own rate limiting.

## Gotchas

1. **Mapbox and Google failures without a response lose the provider error.** The `TypeError`
   from the `.catch` replaces it. Source: `src/services/mapbox.ts`, `src/services/google.ts`
   (`request`).
2. **The Repliers timeout does not cover the throttle queue.** Source:
   `src/services/repliers/base.ts` (constructor and `switchKey`: the axios instance is wrapped by
   `activeThrottler()`), `src/providers/throttler/ondelay.ts`.
3. **A failed HTTP response does not mean nothing happened.** Rows, published messages, Repliers
   clients and messages sent before the error stay. Source: `src/services/boss/webhook.ts`,
   `src/services/agent.ts` (`syncBossPeople`), `src/services/auth.ts`
   ([side effects](/architecture/authentication#side-effects-and-failures)).

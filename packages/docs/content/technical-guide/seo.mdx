Source review: `e30dd9b47`, 2026-11-02. Metadata, canonical URLs, sitemap membership
and robots rules are separate decisions. A routable page is not automatically

## Sitemap inventory

There are six metadata `sitemap.ts` files: `author`, `blog`, `condo`, `condos`,
`dashboard` and `locations`. Reconcile this list when routes change with the
inventory command below.

The XML route handlers separately implement the top-level index, static content,
listing index/chunks and bundled documentation sitemaps. `locations/_sitemap.ts`
is a commented implementation artifact, not an active metadata route. Feature
gates suppress relevant sitemap output; `DISABLE_SSG` is checked by individual
generators and is not a universal sitemap switch.

```powershell
rg --files packages/portal-frontend/src/app -g sitemap.ts -g route.ts
```

The index includes listing sitemaps under the map feature, locations/dashboard
under their own flags, blog and author under blog, and condos/condo under buildings.
`documentationOnly()` suppresses portal entries and makes robots allow
`/documentation` under a general disallow rule. Documentation entries are built
from the available exported sites rather than hard-coded article names.

## Worked failure: listing metadata

The listing page and its metadata call the cached `fetchListing` helper with parsed
MLS and board identity. On a transient API error, metadata uses the missing-property
copy with `{ index: false, follow: true }`; the body attempts nearby listings and
renders `Listing40XTemplate`. This is not evidence that the MLS record was deleted.
Check the API status before treating a fallback page as a genuine missing listing.

## Change verification

1. Confirm domain, indexing policy, route features and source identity for the build.
2. Inspect the rendered title, canonical, robots and social-image URLs for one
   representative route, including an alternate path and a missing record.
3. Follow the sitemap index into its child XML; verify actual URL content and
   feature exclusions, not only HTTP 200.
4. Reconcile generated rewrites/redirects with canonical destinations. Invalidate
   both aliased and destination paths when the content changes.

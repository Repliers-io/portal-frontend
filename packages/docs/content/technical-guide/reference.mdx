# Reference

Quick lookup tables for common values, codes, and configurations.

## Listing Statuses

The MLS `status` field is coarse — only two values. Granular states (sold,
expired, leased, price change, …) live in the separate `lastStatus` field as
3-character codes.

### `status`

| Code | Meaning     | Description                               |
| ---- | ----------- | ----------------------------------------- |
| `A`  | Active      | On-market / available                     |
| `U`  | Unavailable | Off-market (sold, expired, terminated, …) |

### `lastStatus`

3-character codes mapped to display labels in
`configs/defaults/listings.ts` (`statusLabels`).

| Code  | Label                                   |
| ----- | --------------------------------------- |
| `Sus` | Suspended                               |
| `Exp` | Expired                                 |
| `Sld` | Sold                                    |
| `Ter` | Terminated                              |
| `Dft` | Deal Fell Through                       |
| `Lsd` | Leased                                  |
| `Sc`  | Sold Conditionally                      |
| `Sce` | Sold Conditionally with Escape Clause   |
| `Lc`  | Leased Conditionally                    |
| `Lce` | Leased Conditionally with Escape Clause |
| `Pc`  | Price Change                            |
| `Ext` | Extension                               |
| `New` | New                                     |
| `Cs`  | Coming Soon                             |

### Usage

```typescript
// Coarse availability
if (listing.status === 'A') {
  // Show "Active" badge
}

// Granular state via lastStatus
const soldListings = listings.filter((l) => l.lastStatus === 'Sld')
```

## Listing Types

The `listingType` filter keys. Each key is a query fragment (`class` / `propertyType` /
`style`) declared per tenant in `@configs/filters` `listingTypeDeclaration`; the MLS values
behind a key differ per board. Default selector (`listingTypes`):

| Key            | Type                                                |
| -------------- | --------------------------------------------------- |
| `allListings`  | All listings — derived: union of the rendered types |
| `residential`  | Residential                                         |
| `condo`        | Condo                                               |
| `townhome`     | Townhome (class-agnostic)                           |
| `semiDetached` | Semi-Detached                                       |
| `multiFamily`  | Multi-Family                                        |
| `land`         | Land                                                |
| `business`     | Business                                            |
| `commercial`   | Commercial                                          |

Keys a tenant may add (`availableListingTypes`): `residentialTownhome`, `condoTownhome`,
`coop` (co-ops; SERHANT declares it as the `Stock Cooperative` style), `other` (catch-all
bucket), and the derived `penthouse` / `loft` search shortcuts.

### Usage

```typescript
const { addFilters } = useSearchActions()

addFilters({ listingType: 'condo' })
// multi-select tenants (`multiListingType: true`)
addFilters({ listingType: ['residential', 'townhome'] })
```

## Sort Options

| Code              | Description    | Direction     |
| ----------------- | -------------- | ------------- |
| `listPriceAsc`    | Price          | Low to High   |
| `listPriceDesc`   | Price          | High to Low   |
| `soldDateDesc`    | Sold Date      | Newest first  |
| `updatedOnDesc`   | Updated        | Most recent   |
| `bedsDesc`        | Bedrooms       | Most first    |
| `sqftDesc`        | Square Feet    | Largest first |
| `daysOnMarketAsc` | Days on Market | Newest first  |

### Usage

```typescript
// Set sort
setFilters({ ...filters, sortBy: 'listPriceDesc' })
```

## Feature Flags

Static per-tenant flags from `configs/<tenant>/features.ts` (the `defaults`
build ships 22 flags). The full list with descriptions, defaults, dependencies,
and how flags are set lives in
[Capabilities & Flags](/getting-started/capabilities-and-flags). Defaults below
are the `configs/defaults/features.ts` values.

| Flag                     | Description                         | Default |
| ------------------------ | ----------------------------------- | ------- |
| `map`                    | Interactive map search              | `true`  |
| `estimate`               | Home valuation / AVM                | `true`  |
| `dashboard`              | Market dashboard                    | `true`  |
| `blog`                   | Blog section (CMS)                  | `true`  |
| `locations`              | Locations directory                 | `false` |
| `buildings`              | Buildings directory                 | `false` |
| `openHouse`              | Open houses                         | `false` |
| `favorites`              | Save favorite listings              | `true`  |
| `saveSearch`             | Save search filters                 | `true`  |
| `liveBy`                 | LiveBy demographics / overlays      | `true`  |
| `aiSearch`               | Natural-language query parsing      | `true`  |
| `aiChat`                 | Conversational AI chat in search    | `true`  |
| `aiAgent`                | AI agent (embedded EVAS iframe)     | `false` |
| `blurRestrictedProperty` | Blur restricted listings for guests | `false` |

### Usage

```typescript
import features from '@configs/features'

// Page-level gate
if (!features.blog) return <Page40XTemplate />

// Conditional render
{features.aiChat && <AIChatWidget />}
```

## URL Parameters

### Search Filters

The map URL serializes non-default **Filters field names**, not a translation of every entry in `@configs/params`. The server reads those same keys against `defaultFilters` and `defaultAdvancedFilters`. Values and available listing types depend on the configured dataset.

| URL field | Meaning | Owner |
| --- | --- | --- |
| `city`, `area`, `neighborhood`, `locationId` | Geographic filters | Search state |
| `listingType` | Configured property-type key, for example `condo` | Filters declaration |
| `listingStatus` | Configured UI status | Filters declaration |
| `type` | `sale` or `lease`, not a property type | Transaction axis |
| `minPrice`, `maxPrice`, `minBedrooms`, `minBaths` | Numeric filters | Filters defaults/parser |
| `sortBy` | API sort token | Search state |
| `page` | Grid page; omitted at page 1 | Map URL writer |
| Bare `lat,lng` key, `z` | Camera | Map URL codec |
| `layers`, `3d`, `ms` | Overlay, orientation, style | Map options |

### Example URL

A synthetic example, not a promise of results in every dataset:

`/search/map?city=Exampleville&minPrice=500000&minBedrooms=2&listingType=condo`

See [URL & State Synchronization](/technical-guide/url-state-sync) for parsing, omitted defaults, repeated values and the distinction between URL state and API parameters. Source: `src/utils/map/urls.ts` (`getMapUrl`), `src/app/search/[layout]/_utils.ts` (`getFiltersFromParams`).

## API Endpoints

The canonical frontend client map is [API Services](/technical-guide/api-services). Search uses `/listings/search` (GET or POST); profile update uses `PATCH /user`. These are relative to the configured backend API base, not necessarily same-origin Next.js routes.

Source: `src/services/API/APISearch.ts` (`fetch`, `search`), `src/services/API/APIUser.ts` (`update`). Avoid copying the backend endpoint catalogue here: caller behavior belongs to the service page, and backend validation/ownership belongs to the backend contract.

## Board IDs

The MLS feed is identified by a numeric `boardId`, set per tenant in `configs/<tenant>/search.ts`
(`defaultBoardId` = the board listing details are read from; `distinctBoardIds` = boards
addressed by their own id — see
[Regional & MLS Limits](/getting-started/regional-and-mls-limits#multi-board-idx-vs-vow)).
Known board ids and the MLS / region they map to:

| Board id | MLS         | Region                                |
| -------- | ----------- | ------------------------------------- |
| `2`      | TRREB       | Toronto / GTA, ON                     |
| `18`     | CREB        | Calgary, AB                           |
| `68`     | MLS PIN     | Boston, MA                            |
| `71`     | SmartMLS    | Connecticut, USA                      |
| `90`     | TRREB (VOW) | Toronto / GTA, ON                     |
| `91`     | TRREB (IDX) | Toronto / GTA, ON                     |
| `110`    | —           | sample / demo data (`defaults` build) |
| `149`    | NWMLS       | Seattle, WA                           |

## Breakpoints

Custom values from `configs/defaults/theme/breakpoints.ts` — they **override the MUI defaults**
(600/900/1200/1536):

| Name | Width   | Usage         |
| ---- | ------- | ------------- |
| `xs` | 0px+    | Mobile        |
| `sm` | 640px+  | Tablet        |
| `md` | 960px+  | Small desktop |
| `lg` | 1280px+ | Desktop       |
| `xl` | 1920px+ | Large desktop |

### Usage

```tsx
import { useMediaQuery, useTheme } from '@mui/material'

const theme = useTheme()
const isMobile = useMediaQuery(theme.breakpoints.down('sm'))
```
